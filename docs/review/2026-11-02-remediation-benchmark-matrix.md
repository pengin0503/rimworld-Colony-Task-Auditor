## CIで回す回帰ケース
| 入力・状態 | 期待 |
|---|---|
| 重要作業1/5/20/100件が固定 | 先頭以外にも有限回で検証機会を配分、各スキャンの証明予算上限維持 (#25) |
| 監視の登録・削除・並替・ロード | 対象とカーソルの関連が誤らず、古い対象にAutoしない (#25) |
| PriorityWorkの自然終了/明示手動Clear | 書込みの原因が裏付けられ、安全判定が一貫する (#28) |
| 同一Tickに同じSet/Clearが手動で上書き | 手動指示を勝手に消さず、Autoを安全停止 (#28) |
| Watch有り・Assistance Off | 重要作業の警告閾値が維持、Jobへの自動介入ゼロ (#26) |
| Confirmウィンドウを開いた後に別Scan | 材料・作業者・完了状態を更新、古い実行プレビュー破棄 (#29) |
| 原因別の材料/作業者/到達性/禁止 | 実際の対応先への誘導、裏付けのない操作なし (#27) |
| 停滞中に徴兵/医療/火災/手動Job | 自動優先の実行なし、進捗時計と通知は矛盾しない (#28/#27) |

## 最適化と計測 (#30)
- Scanning: 作業記録100/1000/5000/10000、建築・製造・栽培・採掘の混合。実行時間・GC割当（手段があれば）・スキャン中の例外・`PartialScan`を測定。
- UI: 同一一覧を開き、行100/1000/5000/10000、スクロール初期/末尾でのDraw呼出時間、割当量、初回ソート回数を比較。
- Action: Watch件数0/4/5/100でReady証明に要するスキャン数、`ProofBudget`消費・経過Tick、誤通知を計測。
- In-game: 同一セーブでMOD無効・旧/修正版有効、ゲーム速度同一、TPSとGCを比較。270+ MODは実施可能な場合のみ。CIのコンパイル/純モデルテスト結果をゲームFPS/TPSと呼ばない。
