# Colony Task Auditor：診断から実行支援へ（設計、未実装）
> Status: design only, 2026-11-02

## 意図・決定
停滞を知らせるだけでなく、「誰が、何を変えれば作業が動くか」を提示し、プレイヤー確認の後に限定的な改善操作を行えるようにする。重要作業だけを目立たせる。RimWorldの作業割当・キュー全体を代替するMODにはしない。

**基準:** RimWorld 1.7.4985 rev1269（R2 `rimworld-17/Game-Linux/`、既存解析 `research/vanilla-1.7.4985/`）。実作業時には最新API差分を確認する。現行v1.0.1は利用者による実プレイ確認済み・正常との申告を受けている。これは新機能の検証結果ではない。

**4機能共通の操作モード:** Off / Confirm（初期設定）/ Auto。Confirmは内容・対象・副作用を表示して明示承認後に限り変更する。Autoは機能別許可・対象別許可・範囲・上限に従い変更する。拒否条件、無効なスナップショット、状態変化、競合検出時は提案のみまたは停止。自動による不可逆行為は通常のAuto許可に含めない。

**共通安全性:** 手動で禁止・一時停止された対象を自動解除しない。プレイヤーの後からの変更を優先し、同じ操作を繰り返さない。計算根拠と変更前後を表示し、セーブへの履歴保存・クールダウン・レート上限・マップ別管理を設ける。対象削除・改名・移動・マップ切替・ロード・MOD削除時に破損しない。外部MODが管理する設定は原則読取専用、対応保証のない場合は変更停止。UI/設定は日英同等。

## 対象C2：原因別対処・作業者診断
- 既存 `TaskAuditComponent`の診断項目と根拠を用いて、作業対象ごとの「原因」「候補対策」「操作可能/不可」「確信度」を提示する。
- 材料不足: 不足品名・必要数・在庫/禁制/配送途中の扱いを区別。製造指示で作れる場合、対応する作業台/レシピを提示（自動製造の新規実行は別途許可）。
- 作業者不足: 作業種・制限・必要スキルと作業可能候補を表示。手動でOFFにされた職種、健康・徴兵・就寝・メカや他MODの特殊制御を区別。
- 到達不能・予約・禁止: 原因が裏付けられるまでは変更を勧めない。禁止状態や一時停止は意図的な操作として扱い、自動解除しない。
- Confirm時はユーザーが対象・作業者・作用を確認した場合のみ処理。Autoは「実行しても安全と判定できたアクション」に限定し、失敗または見込みの診断では操作しない。
- 既存のアラートと一覧ウィンドウに対処操作を追加し、対策が使えない場合も理由を説明する。

## 対象C4：重要作業の優先監視・一時支援
- マップ内の指定作業・建築・製造指示・栽培等に「重要」マークを付け、既存の停滞計測と連動して短い警告閾値を指定。監視対象削除後は静かに解除する。
- 不足すると深刻なもの（食料/医療/防衛）の自動推奨は可能。ただし重要判定を勝手に確定せず、初期状態ではユーザーが選択。
- Confirmで「選択した作業者に一度優先を依頼」「一時的に作業優先度を調整」「関連情報を開く」をプレビュー。Autoでは**監視対象かつ明示許可された安全な作業**に限定し、クールダウン・対象/時間上限を設ける。
- 入植者の手動指示、徴兵、救助、医療、消防、危険環境、作業制限を尊重する。危険地帯で強制Jobを作らない。
- 可能な場合はバニラの`Verse.PriorityWork`など一時的な支援を優先し、全作業表への恒久変更は避ける。優先度を一時変更する場合は変更前値を記録し、プレイヤーまたは他MODが後から変更したら復元しない（CAS復元）。
- WorkRoles、Work Tab、Smart Priorities、その他優先度MODが同一値を操作するときは、対象を自動制御しない。互換性が確認できるまで提案/確認だけとする。自動で全作業表を書き換えない。

## UI・保存
- `Window_TaskAudit`の各行に「詳細」「対策」「重要登録」を加え、重要のみの絞り込み、優先対象アラートを表示。監視の真偽とユーザーが設定した緊急性を分ける。
- `AuditorSettings`: 対策別モード/自動許可/監視閾値/クールダウン/作業支援の時間・同時上限、従来の警告設定は維持。
- `MapComponent`: 重要登録した対象のID/マップ/プレイヤー選択履歴、MODによる一時支援のスナップショット、期限、復元要件をScribe保存。ジョブや対象が削除されたときは安全に解放。
- 例外・途中導入/削除・再読込で無限に優先をかけない。自動化OFFは次Tick以降の変更を止め、MODが管理していた一時設定だけ条件付きで復元する。

## 競合・失敗条件
- タスクが「通常の順番待ち」「休眠中」「不明原因」「部分走査」の場合は自動操作なし。
- リスクのある医療・戦闘・火災・動物操作・Mod独自Jobを盲目的に自動発行しない。
- 自動操作の条件を満たさなかったら診断情報は残し、操作は抑止する。
- 既存の250Tickの軽量サンプルと5,000Tickの詳細検査を維持し、対策計算は対象選択/高優先時にのみ段階実行。

## 検収シナリオ
- 資材不足・到達不能・技能不足・全員睡眠/徴兵・建築待ち・停止Bill・自動制御されるWorkTab・手動変更/撤回・削除した監視対象。
- 一時優先後に他MOD/プレイヤーが優先度を変更したら復元で上書きしない。
- 作業完了後の優先設定復元、セーブ/ロード後の二重指示なし、270以上のMODとTPS影響比較。
- 診断・確認・Autoで同じ根拠と安全判定を使用し、日本語・英語UIで操作の副作用を説明。

## アプローチ
- A: 診断のみ—競合しないが操作負担が残る。
- **B: 確認付きで限定操作、必要な機能だけ設定でAuto（採用）**—安全性と実用性を両立。
- C: 汎用Job再配布・全自動優先度制御—競合とセーブ副作用が大きいため不採用。
